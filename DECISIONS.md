# Decision Log

Each important design decision, the alternatives considered, and the evidence behind it.
Evidence paths point to files the code writes in `results/`.

| Decision | Alternatives considered | Why rejected | Evidence (file/figure) | Phase |
|---|---|---|---|---|
| One `config.yaml` for all paths and hyperparameters; seed 42 everywhere | Hard-coded constants per script; argparse-only settings | Hard-coded values drift between scripts and team members; argparse-only settings aren't recorded with the results | `config.yaml`, `results/metrics/environment.json` | 0 |
| Device auto-detect CUDA → MPS → CPU, plus a `--fast` mode (128px, 3 epochs, 25% subset) | GPU-only code; separate laptop scripts | GPU-only blocks team members without a GPU; duplicate scripts would diverge | `src/utils.py` (`get_device`, `apply_fast`) | 0 |
| Keep 3-channel RGB input with ImageNet normalisation even though castings are grey | Convert to 1-channel greyscale | Pretrained ResNet weights expect 3 channels; changing the first layer discards part of the pretrained knowledge we want to test | `config.yaml` (`image`) | 0 |
| Cache Kaggle downloads under `data/kagglehub` and store index paths relative to the project root | Default kagglehub user cache; absolute paths | A hidden per-user cache gives every teammate different absolute paths, so shared `splits/*.csv` would break | `src/data.py` (`download_casting`, `_rel`), `data/index.csv` | 1 |
| Use only `casting_data/` (7,348 labelled 300×300 images); ignore the `casting_512x512/` folder | Merge both folders | The 512px folder is a different resolution and overlaps the same parts, so merging would add hidden duplicates | `results/metrics/eda_summary.json` (`counts`, `image_sizes`) | 1 |
| Near-duplicate threshold = 99th percentile of cross-class nearest-neighbour thumbnail correlation (0.976), grouped with connected components | Fixed hand-picked threshold; exact-hash matching; higher percentiles (99.9th → largest group 16) | Hashes miss the rotated/re-exposed copies that this dataset contains; at the chosen threshold, visual checks show pairs down to r≈0.98 are still the same physical part. Single linkage over-groups (largest group 309 = 4%), which is the safe direction for a leakage-free split | `results/figures/eda_duplicate_similarity.png`, `eda_duplicate_examples.png`, `eda_summary.json` (`duplicates`) | 1 |
| Treat Kaggle's original train/test split as leaky and re-split by duplicate group in Phase 2 | Use Kaggle's split as-is | 279 duplicate groups span Kaggle train and test, so its test score would partly measure memorised copies | `eda_summary.json` (`groups_spanning_orig_train_and_test`) | 1 |
| Keep the 33 cross-label near-duplicates (possible label noise) but flag them | Drop them; relabel by hand | Too few to change training, and we can't relabel reliably without domain experts; flagging lets Phase 4 check whether they explain errors | `results/figures/eda_cross_label_duplicates.png` | 1 |
| Shortcut baseline: logistic regression on hand-crafted stats with group-aware 5-fold CV | Plain stratified CV; no baseline | Plain CV lets copies leak across folds (inflated background AUC 0.868 vs 0.839). Background-only stats reaching AUC 0.84 shows OK and defect photos were taken under different lighting, a shortcut the CNN could learn; Phases 7–8 must test for it | `results/metrics/shortcut_baseline.json`, `results/figures/eda_shortcut_baseline.png` | 1 |
| Split by whole duplicate group with greedy balancing (largest groups first, each to the split furthest below its OK/defect target) | Random image-level split; StratifiedGroupKFold with 40 folds | Image-level splits leak copies across train/test. Fold dealing let 300-image OK groups land in one fold, giving production 20% of OK images instead of 10%; greedy balancing hits every target within 0.1% | `splits/*.csv`, `results/metrics/splits_summary.json` (`ok_frac_actual`, `leakage`), `results/figures/splits_composition.png` | 2 |
| Hold out a `production` split (10% of data) before train/val/test | Only train/val/test | Val is used for early stopping and threshold choice, test for model comparison; a split no phase touches gives one honest final check and data for the demo | `config.yaml` (`production_frac`), `splits/production.csv` | 2 |
| Subsample defects to 10% inside each split, round-robin across duplicate groups | Keep the raw 57% defects; random defect subsample | Real lines have rare defects, so metrics at 57% prevalence would overstate precision. Round-robin keeps one defect per physical part before any second copy (train: 219 defects from 219 distinct groups) | `splits_summary.json` (`n_defect_groups`) | 2 |
| Handle imbalance with a WeightedRandomSampler (~49% defects served per epoch); `weighted_loss` kept as a config option | Plain shuffling; pos_weight only | With 10% defects most batches hold 0–3 defects, so training signal for the class that matters is noisy; Phase 3 can compare against `weighted_loss` | `splits_summary.json` (`sampler`), `src/data.py` (`make_loaders`) | 2 |
| Augment with flips, ±15° rotation (neutral grey fill), brightness/contrast jitter, light blur | No augmentation; heavy elastic/crop augmentation | A round casting viewed from the front is unchanged by flips and small rotations; photometric jitter weakens the background-brightness shortcut (background-only test AUC 0.955 on the final splits). Crops could cut the defect out and make the label wrong | `results/figures/augmentation_examples.png`, `splits_summary.json` (`shortcut_train_to_test`) | 2 |
| Compare four models: scratch CNN, ResNet18 frozen, ResNet18 fine-tuned, MobileNetV3-Small fine-tuned | One model only; larger backbones (ResNet50, EfficientNet) | One model can't show whether pretraining or fine-tuning matter; larger backbones are slow on the team's CPUs and are unlikely to help on 300px grey images. MobileNet gives the cheap end of the latency trade-off for Phase 6 | `results/metrics/model_comparison.csv`, `results/figures/model_comparison.png` | 3 |
| Early stopping and model selection on validation AP; test untouched until Phase 4 | Stop on validation loss; select on test | Loss can keep falling while the ranking of rare defects stops improving; selecting on test would make the test score optimistic | `src/train.py` (`fit`), `results/figures/training_curves.png` | 3 |
| Two learning rates for transfer models (head 1e-3, backbone 1e-4); frozen backbone keeps BatchNorm in eval mode | One learning rate for all weights; let frozen BN update | A high LR on pretrained layers destroys the features we want to reuse; updating BN statistics on a frozen backbone silently changes it | `config.yaml` (`train`), `src/models.py` (`param_groups`, `TransferNet.train`) | 3 |
| Sampler only, no pos_weight on top (unless `imbalance: weighted_loss`) | Sampler + pos_weight | Both together correct the 9:1 imbalance twice and bias the model towards calling everything a defect | `src/train.py` (`make_criterion`) | 3 |
| Report the background-only shortcut baseline next to every model | Compare models only to each other | A CNN must clearly beat what lighting statistics alone achieve, or its accuracy may be the shortcut | `results/metrics/training_history.json` (`background_only_val`) | 3 |
| Data-scarcity experiment at 10/25/50/100% of train for scratch CNN vs fine-tuned ResNet18 | Skip it | Real lines collect few defects; the curve shows how many labelled defects each approach needs | `results/metrics/data_scarcity.csv`, `results/figures/data_scarcity.png` | 3 |
| `--fast` outputs carry a `_fast` suffix (checkpoints, metrics, figures) | Overwrite the same files | Smoke-test numbers (128px, 3 epochs, 12 val defects) must never be confused with or overwrite full-run results | `src/utils.py` (`tagged`) | 3 |
| Report test metrics with 95% intervals from a group bootstrap (resample duplicate groups, 2000 draws), plus paired bootstrap AP differences | Point estimates only; image-level bootstrap | Test holds only 47 defects, so point estimates hide large uncertainty; copies of one part aren't independent, so image-level resampling gives intervals that are too narrow. Shared resamples make "model A beats B" a paired test | `results/metrics/test_metrics.csv` (`ap_ci_*`), `test_metrics.json` (`paired_ap_vs_selected`) | 4 |
| Choose operating thresholds (90%/95% precision) on validation, then apply them unchanged to test | Read precision/recall at the best threshold on test; use 0.5 | Picking the threshold on test reports a precision the line would never actually get. 0.5 is meaningless here: the sampler trains at ~50% defects, so probabilities are inflated for a 10%-defect line (see reliability diagram) | `test_metrics.csv` (`thr_p95_from_val`, `test_precision_p95`), `results/figures/reliability.png` | 4 |
| Selected model = best validation AP from Phase 3, never best test score | Pick the best test model | Selecting on test turns the test set into a second validation set and biases the headline number upward | `test_metrics.json` (`selected_model`) | 4 |
| Error gallery always shows the 6 lowest-scored defects and 6 highest-scored OK parts, errors marked red, possible label noise flagged | Show only misclassified images | A strong model may make 0–2 errors, leaving an empty figure; the hardest cases still show where the decision boundary sits | `results/figures/error_gallery.png` | 4 |
| Per-defect-type analysis on NEU-DET (6 steel defect types) with the same ResNet18 fine-tuning recipe | Hand-label defect types on the castings | The casting data has no type labels and we lack the expertise to add them reliably; NEU is a standard labelled benchmark. NEU validation folder = test; 15% of its train folder = early-stopping val; bounding boxes kept for the Grad-CAM check in Phase 7 | `results/metrics/neu_per_type.json`, `results/figures/neu_confusion_matrix.png`, `data/neu_index.csv` | 4 |
| Threshold = minimum of a smoothed expected-cost curve on validation (kernel density of each class's logit scores), cost ratio 50:1, line prevalence 10% | Minimum of the empirical cost curve; 0.5; 95%-precision threshold; Bayes threshold c_fp/(c_fp+c_fn) after prior correction | The empirical curve is a step function with few val defects; its minimum sat just under the weakest val defect and on test missed 2 of 12 (833 vs 59 per 1000 parts in the fast run). Smoothing gives the defect scores a tail, so the 50:1 ratio pushes the threshold into the good parts. The Bayes threshold assumes calibrated probabilities and rejected 75% of good parts | `results/metrics/threshold_candidates.csv`, `results/figures/cost_curve.png` | 5 |
| Expected cost weights miss and false-reject rates by the configured line prevalence, not the split's defect share | Raw counts on the split | Lets the same curve answer "what does this cost on a line with X% defects" and keeps the result valid if a split's defect share drifts | `src/evaluation.py` (`cost_curve`) | 5 |
| Compare models in cost per 1000 parts, each at its own cost-optimal threshold, with "ship everything" / "reject everything" as reference points | Compare on AP only | AP doesn't say whether a model is worth deploying; a model whose best option is "reject everything" adds nothing over having no model | `results/metrics/model_costs.csv`, `results/figures/model_costs.png` | 5 |
| Sensitivity over cost ratios 5, 20, 50, 100 | Single cost ratio | The 50:1 figure is an assumption; the curve shows how the threshold and the shipped/rejected trade-off move if it's wrong | `results/metrics/cost_sensitivity.csv`, `results/figures/cost_sensitivity.png` | 5 |
| Use the production split once, here, to check the final threshold | Use it earlier for tuning; never use it | It's the only data no choice was tuned on, so it gives the honest deployed cost; using it once at the end keeps it honest | `results/metrics/threshold.json` (`production`) | 5 |
| Time batch 1 (live line, one part at a time) and batch 32, after warm-up, median + p5/p95, plus preprocessing; compare with the 500 ms/part line budget | Single mean timing; batch-only throughput | A live line sees one part at a time, so batch-1 latency is what matters; means hide the slow tail (p95); ignoring decode/resize understates the real budget | `results/metrics/latency.csv`, `results/figures/latency.png` | 6 |
| Grad-CAM sanity score = share of heatmap mass on the part (and on the background ring) divided by that region's share of the image, on images the model flags as defects | Visual inspection only; score over all images | Phase 1 found a background-lighting shortcut, so we need a number that says where the evidence sits. On parts called OK the "defect" map has no real evidence and min-max scaling shows noise, which would dilute the score | `results/metrics/gradcam.json` (`sanity_score_part`, `sanity_score_bg`), `results/figures/gradcam_part_vs_background.png` | 7 |
| Grad-CAM randomisation check (trained vs random-weight model) and NEU pointing game against annotated boxes | Trust the heatmaps as they are | Grad-CAM can highlight image edges regardless of what the model learned (Adebayo et al., 2018); NEU boxes give ground truth for "is it looking at the defect" | `gradcam.json` (`randomization_spearman_mean`, `neu.pointing_game_acc`), `results/figures/gradcam_neu.png` | 7 |
| Shortcut tests by editing images: part only (background greyed), background only (casting greyed), background brightness equalised | Rely on Grad-CAM alone; retrain on cropped images | Editing the input tests the trained model's behaviour directly: a model reading the part falls to chance on background-only and keeps its AP when background brightness is equalised. Fill greys are train-set medians, identical for both classes | `results/metrics/robustness.json` (`shortcut_ap`), `results/figures/shortcut_tests.png` | 8 |
| Robustness: keep the Phase 5 threshold fixed under brightness/contrast/blur/rotation shifts and report recall, false-reject rate and cost as well as AP | Report AP only; re-tune the threshold per shift | A line won't re-tune after a lamp ages; AP can stay high while the fixed threshold starts rejecting most good parts, which only the operating-point numbers show | `robustness.csv` (`recall_at_thr`, `frr_at_thr`), `results/figures/robustness_shift.png` | 8 |
| Demo re-derives the threshold from validation predictions when the cost slider moves; uses full-run artefacts when present, else fast ones (with a warning) | Fixed threshold in the app | Lets a viewer see the cost trade-off from Phase 5 live; the warning stops smoke-run numbers being mistaken for final ones | `app/streamlit_app.py` | 9 |
| Report notes generated from `results/metrics/` by a script, each section labelled full or fast | Hand-written numbers in the report | Hand-copied numbers drift from the code; generated notes are always current and show where each number came from | `report/REPORT_NOTES.md`, `scripts/10_make_report_notes.py` | 10 |
